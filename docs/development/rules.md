# Development rules

## Sources

HydroBEM is developed independently from:

- public literature (papers, books, theses; published tables and figures),
  cited in [references.md](../references.md);
- publicly documented file formats, for the files it reads and writes;
- analytic solutions and our own high-precision reference computations
  (arbitrary precision, verified quadrature);
- standard numerical libraries (faer, NumPy, SciPy, mpmath).

Source code, tables and data of other programs are not copied, and no program
is disassembled, decompiled or inspected internally.

## Records

- `CHANGELOG.md`: the user-visible changes.
- The chapters of [the theory](../theory/README.md) (`docs/theory/NN-*.md`): every method choice
  (**[C]**) with its parameters, derivation and accuracy, written as the present state; the code
  cites the section (`theory §N.M`). The section numbers stay stable; new subjects get new
  sections at the end of their chapter, or a new chapter at the end.
- `tests/data/regression/`: HydroBEM's own results of small problems
  (`tests/python/regression_problems.py`), regenerated by
  `scripts/gen_regression_baselines.py` only after an intended change.
- Every table or constant in the engine is reproducible from a script in this
  repository and a cited derivation; no hand-copied numbers.

## The documents

The documentation is divided by reader (the map of the folders and the reading paths:
[docs/README.md](../README.md)):

- `docs/guide/`: the user guide, one file per topic, for using HydroBEM (how to, with examples);
- `docs/theory/`: the theory in numbered chapters (`01-...md` to `14-...md`, the index
  `README.md`), each with the physics of its topic, then the method, then its accuracy;
- `docs/reference/`: what to look up: the inputs by object (`inputs-*.md`), the queries, the
  results, the output files, the Rust API and the C ABI; the generated parts (the tree of the
  inputs, the result views) are written by their scripts between their markers;
- `docs/validation/`: the test plan and the validation report;
- `docs/development/`: these rules, the design, the module map, and the error maps of the tables
  (`error-maps/`, written by their scripts);
- `docs/references.md`: the bibliography.

A section is cited by its folder, file and number (Table 1); within the same file (and within the
theory) by its number alone. `scripts/rewrite_doc_refs.py --check` (run by `scripts/test.bat`)
refuses the citation forms of before 2026-11-12 (`physics §N`, `numerics §N`, `second-order §N`,
`inputs §N`, `results-and-files §N`, the files they named and the old folder of the error maps) outside the
dated records of the history, and checks that every relative link of the published documents and
its anchor exist; `scripts/rewrite_doc_refs.py` rewrites the old forms.

*Table 1. The citation of a section.*

| Document | Citation | Within the same file |
|---|---|---|
| a chapter or section of the theory, `docs/theory/11-mean-drift.md` | `theory §11`, `theory §11.2` | `§11.2` (also from another chapter) |
| a file of the guide, `docs/guide/meshes-and-bodies.md` | `guide/meshes-and-bodies §1` (the file alone: `guide/meshes-and-bodies`) | `§1` |
| a file of the reference, `docs/reference/inputs-bodies.md` | `reference/inputs-bodies §2.1` (the file alone: `reference/inputs-bodies`) | `§2.1` |
| the test plan | `test-plan A`, `test-plan B` | |

## Notation of the documents

- Formulas in the documents are written in TeX math for GitHub-flavoured Markdown: inline
  `$...$` on one line (no space just inside the delimiters), displayed `$$ ... $$` with the
  delimiters on lines of their own; `\vert` (`\lvert`, `\rvert`) for a bar inside a table, `\lbrace`
  `\rbrace` for braces, `aligned` (not `align`) for several lines, and only the standard macros.
  Code comments, docstrings and the C header keep Unicode (`φ_z − K φ`, `∫_S G V_n dS`).
- A figure has its caption below it, the paragraph `*Figure N. ...*`; a table has its caption
  above it, `*Table N. ...*`; both numbered from 1 on each page and cited by number in the text.
  The generator of the validation report (`validation/`) writes them so.
- `scripts/check_doc_math.py` checks both in every published Markdown file (`docs/`, `README.md`,
  `CHANGELOG.md`, `examples/README.md`; run by `scripts/test.bat`): the delimiters and braces of
  every formula, no Unicode math outside formulas and code, no characters of a wrong code page
  (the mojibake of a file saved in another encoding), and the captions. The generators of
  the documents (`scripts/gen_model_classes.py`, `scripts/gen_result_views.py`,
  `scripts/gen_green_tables.py`, `scripts/gen_green_finite_tables.py`,
  `scripts/panel_rule_error_map.py`) write them so too.

## Repository

The repository is kept to the standard of an open-source project: only files
we may distribute (no paper copies, excerpts beyond short citations, or
third-party program files and outputs), cited sources, dependency licences
listed in THIRD_PARTY_NOTICES.md, and no machine-specific paths in tracked files.
