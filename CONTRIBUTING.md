# Contributing to HydroBEM

Thank you for your interest. HydroBEM is kept to the standard of a published
open-source project: every file is ours to distribute, every source is cited,
and every number in the engine can be regenerated.

## How to contribute

- Report a bug or ask for a feature with an issue (the templates ask for a
  minimal problem and for the reference that defines the result).
- A pull request contains one change with its tests, the documentation it changes (a method
  choice described in `docs/theory/`) and, for a visible change, an entry in `CHANGELOG.md`;
  `scripts/test.*` passes.
- Rust: `cargo fmt --all` (`rustfmt.toml`) and `cargo clippy --workspace --all-targets --release -- -D warnings`
  pass, and the style of the surrounding code; the public Rust API
  ([docs/reference/rust-api.md](docs/reference/rust-api.md)) changes with a raised API version;
  Python: `ruff check` (configured in `pyproject.toml`). Building needs Rust and the MSVC linker (see the
  user guide).

## Sources

HydroBEM is written from public literature (papers, books, theses, published
tables), publicly documented file formats, analytic solutions and our own
high-precision reference computations, with standard numerical libraries
(faer, NumPy, SciPy, mpmath). Cite what you use in `docs/references.md` and
where the method is described.

Do not copy source code, tables or data from other programs, and do not
disassemble, decompile or inspect the internals of any program. Do not commit
copies of papers or manuals (beyond short citations), or files and outputs of
other programs.

## Records

- `CHANGELOG.md`: every user-visible change.
- the chapters of `docs/theory/` (`01-...md` to `14-...md`): every method choice with its
  derivation, its parameters and its accuracy, written as the present state of
  the engine; its sources cited in `docs/references.md`. The code cites the
  section (`theory §8.2`; the citation forms in `docs/development/rules.md`).
- `tests/data/regression/`: HydroBEM's own results of small problems,
  regenerated by `scripts/gen_regression_baselines.py` only after an intended
  change of results, with the reason in the commit.
- Every table or constant of the engine comes from a script in `scripts/`
  with a cited derivation: regenerate, never edit tables by hand.
- No machine-specific paths or personal data in tracked files.

## Tests

Build and test before and after a change (`scripts/build.*`, then
`scripts/test.* fast` while working and `scripts/test.*` (full) before a
commit; see the README). The test plan is
`docs/validation/test-plan.md`:

- component accuracy (`crates/hydrobem/tests/`, `cargo test`) and identities, input rules
  and published results (`tests/python/`); tests of more than a few seconds are marked
  `@pytest.mark.slow` (`scripts/test.* fast` leaves them out);
- regression baselines (`tests/python/test_regression.py`): after an
  intended change of results, regenerate them with
  `scripts/gen_regression_baselines.py` and give the reason in the commit;
- `ruff check` must pass (configuration in `pyproject.toml`).

A combination of inputs the engine cannot solve is rejected explicitly
(`UnsupportedProblemError`), never approximated.

## Interfaces

Options are explicit; one parameter has one meaning (no value that is both a
switch and a setting). An input that can be wrong is checked with a message
naming the rule (reference/inputs-rules §1).
